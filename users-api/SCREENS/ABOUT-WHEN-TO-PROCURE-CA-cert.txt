When would YOU actually need to deal with CA certificates?

Usually when you're dealing with something like:

Company-managed PostgreSQL
        ↓
Private network
        ↓
Custom CA
        ↓
Strict certificate verification

or a database provider explicitly says:

"Download our CA certificate and configure your client to verify the server certificate."

Then you might have:

ssl: {
  rejectUnauthorized: true,
  ca: process.env.DATABASE_CA,
}

But you don't obtain a CA certificate just because your application is going to production.

The simple rule

Vercel handles HTTPS for your React application. Render handles HTTPS for your Node.js API. Your PostgreSQL provider handles the database's TLS infrastructure. You only configure CA certificates yourself when the particular database/enterprise setup requires it.

So for the applications you've been building with React + Node/Express + PostgreSQL + Vercel/Render/Neon, you generally don't need to go to a CA and purchase certificates yourself.
