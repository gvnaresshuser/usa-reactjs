Yes — this is a very common React + Vite + React Router deployment issue, and your application itself is working correctly.

You can navigate to:

https://react-ts-ecom-app-frontend.vercel.app/login

but when you refresh, Vercel tries to find a physical /login file/folder. Since /login is a React Router route rather than a real file, Vercel returns 404 NOT_FOUND. Vercel's own community guidance recommends an SPA rewrite for this situation.

Fix: add vercel.json

Since your repository structure is:

ReactTSEcomApp
│
├── frontend
│   ├── src
│   ├── package.json
│   ├── vite.config.ts
│   └── ...
│
└── backend

Create:

frontend/vercel.json

with:

{
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}

This tells Vercel:

"For any route that isn't a real static file, serve index.html and let React Router decide what page to display."

So:

/login
/products
/cart
/orders
/admin
/admin/dashboard

will all be handled by React Router after refresh.

Important for your project

Because your Vercel project is deploying the frontend folder, put vercel.json here:

ReactTSEcomApp
└── frontend
    ├── src
    ├── public
    ├── package.json
    ├── vite.config.ts
    └── vercel.json   ← HERE

Not inside src.
