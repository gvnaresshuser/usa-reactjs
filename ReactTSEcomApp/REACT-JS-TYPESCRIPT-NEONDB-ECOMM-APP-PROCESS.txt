## 1. Enable UUID

Run this first:

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;
```

```sql
gen_random_uuid()
```

for IDs.

# 2. Users Table

This table handles registration and login.

```sql
CREATE TABLE IF NOT EXISTS users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    name VARCHAR(100) NOT NULL,

    email VARCHAR(255) NOT NULL UNIQUE,

    password_hash TEXT NOT NULL,

    role VARCHAR(20) NOT NULL DEFAULT 'USER'
        CHECK (role IN ('USER', 'ADMIN')),

    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### Simple explanation

```text
users
-----------------------------
id
name
email
password_hash
role
created_at
updated_at
```

For example:

```text
id       → UUID
name     → Naressh
email    → naressh@gmail.com
password → bcrypt hash
role     → USER
```

We **never store the actual password**.

Instead:

```text
password
   ↓
bcrypt
   ↓
password_hash
```

# 3. Products Table

This stores products displayed on the Dashboard.

```sql
CREATE TABLE IF NOT EXISTS products (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    name VARCHAR(200) NOT NULL,

    description TEXT,

    price NUMERIC(12,2) NOT NULL
        CHECK (price >= 0),

    image_url TEXT,

    category VARCHAR(100),

    stock INTEGER NOT NULL DEFAULT 0
        CHECK (stock >= 0),

    is_active BOOLEAN NOT NULL DEFAULT TRUE,

    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

Example:

```text
products
------------------------------------------------
id
name
description
price
image_url
category
stock
is_active
created_at
updated_at
```

Example data:

```text
iPhone 17
₹79999
Electronics
Stock: 10
```

# 4. Orders Table

This represents the customer's order.

```sql
CREATE TABLE IF NOT EXISTS orders (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    user_id UUID NOT NULL
        REFERENCES users(id)
        ON DELETE RESTRICT,

    total_amount NUMERIC(12,2) NOT NULL
        CHECK (total_amount >= 0),

    status VARCHAR(30) NOT NULL DEFAULT 'Pending'
        CHECK (
            status IN (
                'Pending',
                'Cancelled',
                'Packed',
                'OutForDelivery',
                'Delivered'
            )
        ),

    payment_status VARCHAR(20) NOT NULL DEFAULT 'Pending'
        CHECK (
            payment_status IN (
                'Pending',
                'Paid',
                'Failed',
                'Refunded'
            )
        ),

    razorpay_order_id VARCHAR(255),

    razorpay_payment_id VARCHAR(255),

    razorpay_signature TEXT,

    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

This table connects the customer with their order.

For example:

```text
User
  ↓
Naressh
  ↓
Order #123
  ↓
₹25,000
  ↓
Paid
  ↓
Packed
```

# 5. Order Items Table

This is particularly important.

An order can contain multiple products.

```sql
CREATE TABLE IF NOT EXISTS order_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    order_id UUID NOT NULL
        REFERENCES orders(id)
        ON DELETE CASCADE,

    product_id UUID NOT NULL
        REFERENCES products(id)
        ON DELETE RESTRICT,

    product_name VARCHAR(200) NOT NULL,

    price NUMERIC(12,2) NOT NULL
        CHECK (price >= 0),

    quantity INTEGER NOT NULL
        CHECK (quantity > 0),

    subtotal NUMERIC(12,2) NOT NULL
        CHECK (subtotal >= 0),

    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

Why do we store:

```text
product_name
price
```

again here?

Because suppose today:

```text
Laptop = ₹50,000
```

Customer buys it.

The order stores:

```text
Laptop
₹50,000
```

Tomorrow the admin changes the product price:

```text
Laptop = ₹55,000
```

The old order should **still show ₹50,000**.

Therefore:

```text
products.price
       ↓
current price

order_items.price
       ↓
historical purchase price
```

This is a very important ecommerce concept.

---

# 7. Why We Need Indexes

For example, when the customer opens:

```text
My Orders
```

we'll execute something like:

```sql
SELECT *
FROM orders
WHERE user_id = $1;
```

Therefore:

```text
idx_orders_user_id
```

helps PostgreSQL find those orders efficiently.

Similarly, Admin will do:

```sql
SELECT *
FROM orders
ORDER BY created_at DESC;
```

so:

```text
idx_orders_created_at
```

is useful.
