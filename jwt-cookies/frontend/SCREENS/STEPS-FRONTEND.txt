Login
  ↓

  ↓
POST /api/auth/refresh
  ↓
Refresh Token validated
  ↓
New Access Token generated
  ↓
Original request automatically retried
  ↓
User continues without logging in again

******************************************************
The correct JWT flow
When the access token expires:
Access Token Expired
        ↓
SweetAlert:
"Session expired. Refreshing access token..."
        ↓
Refresh Token
        ↓
New Access Token
        ↓
Retry original request

When the refresh token is still valid, our backend can also rotate it and generate a new refresh token:
Refresh Token Valid
        ↓
Generate new Access Token
        +
Generate new Refresh Token
        ↓
Store new refresh token
        ↓
Continue session

But if the refresh token itself has expired:
Access Token Expired
        ↓
Try Refresh Token
        ↓
Refresh Token Expired ❌
        ↓
Cannot generate a new refresh token
        ↓
SweetAlert:
"Your session has expired.
Please login again."
        ↓
Redirect to Login

So:
F5 every 5 seconds
       ↓
Access token eventually expires
       ↓
Refresh succeeds
       ↓
Refresh token rotated
       ↓
New refresh-token lifetime
       ↓
Session continues

This is called a "sliding session"
Our current design effectively creates a sliding refresh-token session.
